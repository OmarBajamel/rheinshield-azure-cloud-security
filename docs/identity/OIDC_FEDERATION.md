# GitHub Actions OIDC federation

The workflow requests `id-token: write` and `contents: read`, then exchanges GitHub's short-lived token for Azure access with audience `api://AzureADTokenExchange`. Trust is bound to the exact public repository, protected `azure-lab` environment, branch/ref policy, and the current immutable-subject behavior described in the official source register. Pull-request code from forks cannot access the environment.

`scripts/bootstrap-azure.ps1` and `.sh` implement the one-time operator path. Before mutation they refuse any pre-existing exact-name group or same-display-name application; they always create a new app/service principal, verify the exact repository/environment subject and audience, and store immutable object IDs only in `.private/azure-bootstrap.env`. They grant only `Reader` on the three new groups because the hosted workflow is deliberately plan-only. No `AZURE_CLIENT_SECRET` exists and the workflow has no apply path.

The GitHub workflow is main-branch, exact-repository, protected-environment, plan-only. The script verifies GitHub's repository, ref, event and immutable workflow-ref context; it does not require Microsoft Graph permissions to re-read the app registration. A local apply is an operator-authenticated, retained-state operation with private bootstrap provenance and a plan/hash-bound Infracost gate. Teardown requires a saved 15-minute plan and the private bootstrap provenance, then removes and verifies both the resource groups and exact Entra identity. `cleanup-bootstrap-identity.*` is also available for recovery by the original bootstrap operator.
